# 一键发布

此流程适用于已按指导配置好 `orderdeploy` 账号、SSH 密钥和服务器发布入口的电脑。

1. 在本地完成修改和测试，检查 `git status` 和 `git diff --cached`，只提交已经审查的文件。
   不要误提交 `.env`、数据库、备份、SSH 私钥或无关的暂存文件。
2. 在 PowerShell 运行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Order Record\deploy\publish.ps1"
   ```

3. 确认显示的提交版本已审查、没有数据库结构或数据迁移，输入 `RELEASE`。
   脚本只构建当前 Git 提交，不包含未提交或暂存的修改，也不会自动提交或推送 Git。
4. 按提示输入发布密钥的口令。当前 SSH agent 未启用，一次发布可能需要输入多次口令。
5. 发布结束后，访问正式网站并登录，检查关键功能。

脚本在本机隔离目录安装依赖、检查类型、运行安全、业务规则及看板测试并构建前端；服务器使用普通发布账号
安装 Linux 依赖，预览通过后再切换生产服务。部署需要本机和服务器能够下载依赖。

如果启动检查失败，脚本会尝试恢复原来的服务配置并检查服务；自动回退不能保证一定成功，
也不能撤销数据库变更。数据库结构、数据迁移及其他可能影响生产数据的代码必须单独审查、
确认备份和回退方案后再发布。脚本对数据库文件的检查不可能识别所有此类变更。

以下 MySQL 结构变更脚本分别对应待派单状态调整、联系人/项目组、业务来源/业务程度，以及状态合并与实际完成日期：

- `server/src/migration-pending-reset.sql`
- `server/src/migration-contact-team.sql`
- `server/src/migration-business.sql`
- `server/src/migration-status-completion.sql`

现有自动发布脚本会在检测到数据库文件变化时停止；上线前需按上述顺序单独审查并验证备份、
迁移、旧版兼容性和回退方案，不能直接运行一键发布绕过检查。应用启动不会自动执行这些 SQL。

发布账号不能直接运行任意管理员命令，但它发布的应用代码可以使用应用自身的权限，
包括访问生产数据库。因此，必须保护发布密钥，仅发布可信、已审核的提交。

发布脚本和说明应随项目维护；现有无关暂存文件不应因此被自动提交。
